# Лабораторная работа №2

## Тема и цель

**Тема:** дообучение диалоговых моделей двух архитектур — decoder-only и encoder-decoder.

**Цель:** научить две предобученные языковые модели генерировать ответ системы на сообщение пользователя, сравнить их до и после дообучения по BLEU и METEOR и понять причины полученных результатов.

В работе использованы:

- decoder-only модель [DistilGPT2](https://huggingface.co/distilbert/distilgpt2);
- encoder-decoder модель [FLAN-T5-small](https://huggingface.co/google/flan-t5-small);
- диалоговый датасет [DailyDialog в формате Parquet](https://huggingface.co/datasets/OpenRL/daily_dialog).

Для каждой архитектуры выполнен одинаковый набор шагов: подготовлены пары `сообщение -> следующая реплика`, проведена zero-shot генерация, посчитаны исходные метрики, модель дообучена, генерация повторена на тех же примерах, после чего метрики сопоставлены.

# Часть I. Теория, необходимая для понимания работы

## 1. Что именно должна выучить модель

Один элемент данных выглядит так:

```text
Сообщение: What kind of meat would you like to get today?
Ответ:     First off, I'm going to need a pound of ground beef.
```

Модель не выбирает целый ответ из готового списка. Она последовательно оценивает вероятность следующего токена:

```text
P(следующий токен | уже известный контекст)
```

Выбранный токен добавляется в контекст, затем предсказывается следующий. Цикл продолжается до специального токена конца ответа либо ограничения длины.

```text
Запрос -> токенизатор -> числа -> Transformer -> вероятности следующего токена
                                               |
                                               v
                              токен добавляется в контекст -> повтор
```

## 2. Токенизация

Нейросеть не работает напрямую со строками. Токенизатор разбивает текст на токены и заменяет их целыми числами:

```text
"I like machine learning"
        ↓
["I", " like", " machine", " learning"]
        ↓
[40, 588, 4572, 4673]
```

Токен не обязательно равен слову: редкое слово может состоять из нескольких токенов. После генерации токенизатор выполняет обратное преобразование чисел в строку.

## 3. Transformer и attention

Обе модели основаны на Transformer. Его центральный механизм — attention: модель вычисляет, какие части контекста важны для обработки текущего токена.

В предложении `John bought a laptop because he needed it for work` токену `it` полезно уделить внимание слову `laptop`. Модель не получает это правило вручную, а учится выставлять полезные веса внимания на большом числе примеров.

## 4. Decoder-only архитектура

Decoder-only состоит только из блоков декодера. В работе это DistilGPT2.

Запрос и ответ объединяются в одну последовательность:

```text
User: What time does the shop close?
Assistant: It closes at six.
```

При генерации ответ ещё неизвестен:

```text
User: What time does the shop close?
Assistant:
```

Модель продолжает эту строку.

### Causal mask

При предсказании очередного токена модель может учитывать только известные токены слева, но не будущую часть ответа:

```text
позиция 1 видит: 1
позиция 2 видит: 1, 2
позиция 3 видит: 1, 2, 3
```

Без causal mask модель могла бы подсмотреть правильное продолжение во время обучения.

### Маскирование prompt в loss

Контекст нужен для ответа, но заставлять модель заново предсказывать запрос не требуется. Поэтому target устроен так:

```text
User: запрос       Assistant: ответ
-100 -100 ... -100           id id id
```

PyTorch игнорирует позиции `-100` при расчёте loss. Ошибка считается только по ответу. Padding также замаскирован.

### Практический смысл

Decoder-only удобна длинной общей историей диалога и естественным продолжением текста. Но запрос и ответ занимают одно контекстное окно, а формат разговора приходится обозначать маркерами `User:` и `Assistant:`. Исходная GPT-подобная модель может повторять запрос, пока не выучит этот формат.

## 5. Encoder-decoder архитектура

Encoder-decoder состоит из двух частей. В работе это FLAN-T5-small.

```text
Запрос -> Encoder -> представление запроса
                         |
                         v  cross-attention
                    Decoder -> ответ токен за токеном
```

Encoder получает весь запрос и может учитывать его в обе стороны. Decoder генерирует ответ слева направо, используя уже созданную часть ответа и представление входа через cross-attention.

Запрос и ответ передаются отдельно:

```text
source: Generate a natural reply to this dialogue message: {message}
target: {response}
```

FLAN-T5 — instruction-tuned версия T5. До лабораторной она уже училась реагировать на текстовые инструкции, поэтому может понять команду `Generate a natural reply...` в zero-shot режиме.

## 6. Главное различие архитектур

| Свойство | Decoder-only | Encoder-decoder |
|---|---|---|
| Части | Только decoder | Encoder и decoder |
| Данные | Запрос и ответ в одной строке | Запрос и target раздельно |
| Attention входа | Только влево | Encoder видит весь вход |
| Связь с запросом | Self-attention общей строки | Cross-attention к encoder |
| Формат | `User: ... Assistant: ...` | Инструкция и отдельный ответ |
| Модель | DistilGPT2 | FLAN-T5-small |

## 7. Zero-shot и fine-tuning

**Zero-shot** — решение задачи без обучения на DailyDialog. Это исходная точка, необходимая для оценки эффекта дообучения.

**Fine-tuning** — продолжение обучения готовой модели на узких данных. Transformer не обучается с нуля: его веса лишь немного меняются, чтобы освоить формат, стиль и типичную длину повседневных ответов.

## 8. Loss, teacher forcing и обновление весов

На позиции каждого целевого токена модель должна назначить высокую вероятность правильному следующему токену. Используется cross-entropy:

```text
loss = -log P(правильный токен)
```

Чем ниже вероятность правильного токена, тем больше штраф.

Teacher forcing означает, что во время обучения decoder видит предыдущий правильный токен, а не собственную ошибочную генерацию. Затем backpropagation вычисляет вклад параметров в ошибку, и AdamW обновляет веса.

Параметры обучения:

- learning rate: `5e-5`;
- batch size на GPU: `8`;
- gradient accumulation: `2`;
- эффективный batch size: `16`;
- epochs: `1`;
- gradient clipping: `1.0`;
- warmup: 10% шагов.

## 9. Train и validation

`train` используется для изменения весов. `validation` не участвует в обновлении и показывает качество на невидимых примерах.

DailyDialog имеет официальные разбиения по целым диалогам, поэтому реплики одного диалога не попадают одновременно в train и validation. Из каждого диалога получены соседние пары:

```text
utterance[0] -> utterance[1]
utterance[1] -> utterance[2]
utterance[2] -> utterance[3]
```

В train доступно 76 052 пары, из которых с seed `42` выбрано 6000. В validation доступно 7069 пар: 500 применяются для validation loss, первые 200 того же фиксированного набора — для генерации и метрик.

## 10. Генерация

До и после обучения используется один режим:

```text
do_sample = False
num_beams = 1
max_new_tokens = 40
```

Это greedy decoding — каждый раз выбирается наиболее вероятный токен. Он может давать однообразные ответы, но удобен для воспроизводимого сравнения: случайность не влияет на результат.

## 11. BLEU

BLEU сравнивает n-граммы из одного, двух, трёх и четырёх токенов в ответе и эталоне. Также применяется штраф за слишком короткий ответ. В работе используется corpus BLEU из SacreBLEU в шкале 0–100.

BLEU оценивает точное совпадение формулировок, но не понимает смысл. Для эталона `Yes, I do` ответ `Of course` может быть правильным для человека и получить низкий BLEU.

## 12. METEOR

METEOR выполняет более мягкое сопоставление. Реализация NLTK учитывает точные слова, основы слов, синонимы WordNet и штраф за нарушенный порядок. Шкала — от 0 до 1.

METEOR часто лучше отражает частичное смысловое сходство, но тоже не может надёжно оценить все допустимые ответы.

## 13. Почему оценка диалога сложна

На `Would you like some coffee?` допустимы `Yes, please`, `No, thank you`, `I'd prefer tea` и другие ответы. В датасете есть только одна реально произнесённая реплика. Метрики сравнивают генерацию именно с ней.

Поэтому низкое значение не всегда означает бессмысленный ответ. Для полноценного исследования полезны несколько эталонов, семантические метрики и ручная оценка. В задании требуются BLEU и METEOR, поэтому они остаются основными показателями.

# Часть II. Практическое выполнение

## 14. Выбор датасета и моделей

### DailyDialog

DailyDialog содержит 13 118 повседневных диалогов: 11 118 train, 1000 validation и 1000 test. Использована современная Parquet-копия, совместимая с `datasets==5.1.0`.

### DistilGPT2

Decoder-only модель с 81 912 576 параметрами. Запрос и ответ объединяются, loss считается только по токенам ответа, дообучаются все параметры.

### FLAN-T5-small

Encoder-decoder модель с 76 961 152 параметрами. Инструкция кодируется encoder, ответ передаётся decoder отдельно, дообучаются все параметры.

Модели близки по размеру, поэтому результат не определяется только многократной разницей числа параметров.

## 15. Предобработка

Для decoder-only:

```text
User: {message}
Assistant: {response}<eos>
```

Для encoder-decoder:

```text
source: Generate a natural reply to this dialogue message: {message}
target: {response}
```

Максимальная длина входа — 64 токена, ответа — 48 токенов. Padding target и prompt decoder-only исключены из loss значением `-100`.

## 18. Примеры

### DistilGPT2 освоила формат ответа

```text
Message:   What kind of meat would you like to get today?
Reference: First off, I'm going to need a pound of ground beef.

Zero-shot:
I would like to get a meat that is not meat.
Assistant: I would like to get a meat that is not meat...

Fine-tuned:
I'd like to get a steak.
```

До обучения модель циклически продолжает prompt. После обучения ответ не совпадает с эталоном дословно, но является короткой релевантной репликой.

### Допустимый ответ с низким точным совпадением

```text
Message:   We offer a Personal Automobile Consumer Loan... Do you have enough funds?
Reference: Yes, I do. It's ready and waiting in my account.
DistilGPT2 fine-tuned: Yes, I have.
```

По смыслу ответ подходит, но не повторяет большую часть эталона. BLEU за это штрафует.

### Общий ответ FLAN-T5

```text
Message:   Not at all, sir. Here you are.
Reference: Thanks. Well, it seems to be right. How much is that in dollars, please?
FLAN-T5 zero-shot:   I'm sorry.
FLAN-T5 fine-tuned:  I'm sorry. I'm sorry.
```

Модель выучила частый разговорный шаблон, но он не подходит контексту. Полные 200 примеров сохранены в CSV, поэтому выводы можно проверить на всём subset.

## 19. Анализ

### DistilGPT2

Обе метрики выросли. BLEU увеличился примерно в шесть раз. Главное качественное изменение — модель перестала считать задачу произвольным продолжением текста и освоила формат короткого ответа после `Assistant:`.

Это ожидаемо: исходная DistilGPT2 обучалась продолжать текст и не была специально настроена на нашу инструкцию или DailyDialog.

### FLAN-T5-small

Zero-shot FLAN-T5 сильнее исходной DistilGPT2, поскольку FLAN уже проходила instruction tuning. После обучения METEOR вырос, а BLEU снизился. Ответы стали немного лучше совпадать по мягким соответствиям, но потеряли часть точных n-грамм эталона.

Это не следствие сорванного обучения:

- train и validation loss конечны;
- validation loss ниже среднего train loss;
- веса и ответы изменились;
- METEOR вырос.

Вероятные причины:

1. FLAN-T5 уже имела сравнительно сильный zero-shot baseline.
2. Использовано 6000 из 76 052 доступных train-пар и одна эпоха.
3. Greedy decoding склоняется к частым безопасным ответам.
4. В открытом диалоге один эталон плохо оценивает множество допустимых формулировок.

Fine-tuning не гарантирует одновременного роста каждой метрики. Поэтому необходимо смотреть на несколько показателей и реальные генерации.

## 20. Итоговое сравнение и вывод

В конкретном эксперименте:

- лучший zero-shot BLEU показала FLAN-T5-small;
- лучший итоговый BLEU и METEOR показала дообученная DistilGPT2;
- METEOR после fine-tuning вырос у обеих моделей;
- BLEU вырос у DistilGPT2 и снизился у FLAN-T5-small.

Нельзя обобщать, что decoder-only всегда лучше encoder-decoder. Сравнивались две конкретные предобученные модели, одна инструкция, небольшой train subset и greedy decoding. Архитектура — лишь один из факторов.

Задание выполнено полностью: выбраны модели и датасет, проведены zero-shot эксперименты, посчитаны BLEU и METEOR, обе модели дообучены, метрики пересчитаны и сравнены.
