# Лабораторная работа №1

## Сравнение mean pooling и CLS pooling в задаче классификации текстов

## 1. Цель работы

Нужно обучить модель векторизации текста решать задачу многоклассовой классификации, используя две стратегии получения единого вектора текста:

1. `mean pooling` — усреднение векторов токенов;
2. `CLS pooling` — использование вектора специального токена `[CLS]`.

Для обеих стратегий требуется посчитать Precision, Recall и F1-score, затем сравнить результаты.

В работе использовались:

- датасет [AG News](https://huggingface.co/datasets/fancyzhx/ag_news);
- encoder-модель [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2);
- полное дообучение encoder и классификационного слоя;
- одинаковые данные и гиперпараметры для двух экспериментов.

## 2. Общая схема решения

Обработка одного текста выглядит так:

```text
исходный текст
    ↓
токенизатор
    ↓
последовательность токенов
    ↓
Transformer encoder
    ↓
отдельный вектор для каждого токена
    ↓
mean pooling или CLS pooling
    ↓
один вектор всего текста
    ↓
линейный классификатор
    ↓
четыре числа — logits классов
    ↓
класс с наибольшим logit
```

Главная часть лабораторной находится в середине этой схемы: нужно сравнить два способа преобразования набора векторов токенов в один вектор текста.

# Теоретическая часть

## 3. Что такое классификация текста

Классификация — это выбор одного класса из заранее известного набора.

В AG News используются четыре класса:

- `World` — мировые новости;
- `Sports` — спорт;
- `Business` — бизнес;
- `Sci/Tech` — наука и технологии.

На вход модели поступает текст новости, а на выходе требуется получить номер класса от 0 до 3.

Это именно многоклассовая классификация: классов больше двух, и каждый текст относится ровно к одному классу.

## 4. Почему текст нельзя сразу передать в нейронную сеть

Нейронные сети работают с числами. Строку Python нельзя напрямую умножить на матрицу весов, поэтому текст сначала преобразуется в числовое представление.

Преобразование выполняется в два этапа:

1. токенизатор разбивает текст на токены и заменяет их числовыми идентификаторами;
2. encoder преобразует каждый токен в содержательный числовой вектор.

### 4.1. Токены

Токен не обязательно совпадает со словом. Частое слово может стать одним токеном, а редкое — несколькими частями.

Упрощённый пример:

```text
"unbelievable result"
```

может быть разбит примерно так:

```text
[CLS], un, ##believable, result, [SEP]
```

Точный результат зависит от словаря конкретного токенизатора.

Специальные токены:

- `[CLS]` помещается в начало последовательности;
- `[SEP]` отмечает конец или границу фрагмента;
- `[PAD]` дополняет короткие тексты до общей длины batch.

### 4.2. Зачем нужен padding

GPU эффективно обрабатывает прямоугольные тензоры. Если в batch находится 32 текста разной длины, их нужно привести к одной длине.

Короткие последовательности дополняются токенами `[PAD]`. В этой работе максимальная длина равна 128 токенам:

- длинный текст обрезается до 128 токенов;
- короткий дополняется `[PAD]` до 128.

### 4.3. Attention mask

После padding модели нужно сообщить, какие позиции содержат настоящий текст, а какие являются заполнителями.

Например:

```text
input_ids:      [CLS] news text [SEP] [PAD] [PAD]
attention_mask:   1     1    1     1     0     0
```

Единица означает полезную позицию, ноль — padding.

Attention mask используется и внутри Transformer, и при `mean pooling`. Без неё padding попал бы в среднее значение и исказил вектор текста.

## 5. Что делает Transformer encoder

Encoder получает последовательность токенов и возвращает вектор для каждой позиции.

Если batch имеет форму:

```text
[batch_size, sequence_length]
```

то выход encoder имеет форму:

```text
[batch_size, sequence_length, hidden_size]
```

В выполненном эксперименте:

- `batch_size = 32`;
- `sequence_length = 128`;
- `hidden_size = 384`.

Значит, типичная форма выхода:

```text
[32, 128, 384]
```

Для каждого из 32 текстов получено 128 векторов размерности 384.

Важное свойство encoder-модели: вектор токена зависит от контекста. Вектор слова `bank` в банковской новости и в предложении про берег реки будет различаться.

## 6. Зачем нужен pooling

После encoder у текста остаётся не один вектор, а отдельный вектор для каждого токена. Классификатору удобнее передать один вектор фиксированной длины.

Pooling решает задачу:

```text
[sequence_length, hidden_size] → [hidden_size]
```

То есть в нашем случае:

```text
[128, 384] → [384]
```

## 7. Mean pooling

При `mean pooling` векторы всех непустых токенов усредняются.

Если у текста есть векторы токенов `h₁, h₂, ..., hₙ`, то:

```text
text_vector = (h₁ + h₂ + ... + hₙ) / n
```

В реальном коде учитывается attention mask:

```python
expanded_mask = attention_mask.unsqueeze(-1)
embedding_sum = (token_embeddings * expanded_mask).sum(dim=1)
valid_token_count = expanded_mask.sum(dim=1)
text_vector = embedding_sum / valid_token_count
```

Преимущество подхода: информация собирается непосредственно со всех токенов текста.

Ограничение: все токены получают одинаковый вес. Служебное или малозначимое слово участвует в среднем так же, как важный термин.

## 8. CLS pooling

При `CLS pooling` берётся выходной вектор первой позиции — токена `[CLS]`:

```python
text_vector = token_embeddings[:, 0]
```

Хотя `[CLS]` расположен в начале, механизм self-attention позволяет ему получать информацию от остальных токенов. Во время дообучения модель может научиться собирать в эту позицию признаки, полезные для классификации.

Преимущество подхода: не требуется усреднение, используется одна специально выделенная позиция.

Ограничение: качество зависит от того, насколько предобучение и последующее дообучение модели подготовили `[CLS]` к роли общего представления текста.

Поэтому нельзя заранее утверждать, что один pooling всегда лучше другого. Это проверяется экспериментально.

## 9. Классификационный слой

После pooling получается вектор размерности 384. Его нужно преобразовать в четыре значения — по одному для каждого класса.

Используется линейный слой:

```text
384 → 4
```

Математически:

```text
logits = W × text_vector + b
```

`logits` — необработанные оценки классов. Например:

```text
World:    0.4
Sports:  -0.7
Business: 2.1
Sci/Tech: 0.8
```

Модель выберет `Business`, поскольку у этого класса максимальный logit.

Во время обучения `CrossEntropyLoss` внутри себя применяет преобразование, эквивалентное softmax, и сравнивает распределение с правильным классом. Поэтому вручную вызывать softmax перед loss не нужно.

## 10. Что именно обучается

В этой работе обновляются:

- веса Transformer encoder;
- веса линейного классификатора.

Такой режим называется fine-tuning: модель уже знает общие закономерности языка, а затем адаптируется под конкретные классы AG News.

Encoder не замораживался. Это соответствует цели обучить модель векторизации на задаче классификации, а также позволяет векторным представлениям адаптироваться к различиям между новостными категориями.

## 11. Train, validation и test

Данные разделены на три части.

### Train

Используется для вычисления loss и изменения весов модели.

### Validation

Используется после каждой эпохи для выбора лучшего checkpoint. Веса по validation не обновляются.

### Test

Используется один раз после выбора лучшего checkpoint. По test нельзя подбирать настройки, иначе он перестаёт быть независимой проверкой.

В эксперименте:

| Часть | Размер | Назначение |
|---|---:|---|
| Train | 12 000 | Обучение, по 3 000 текстов каждого класса |
| Validation | 4 000 | Выбор checkpoint, по 1 000 текстов каждого класса |
| Test | 7 600 | Полный официальный test split, по 1 900 текстов каждого класса |

Использована стратификация: в каждой части классы представлены поровну.

Полный обучающий split AG News содержит 120 000 текстов. Для лабораторной взята сбалансированная подвыборка из 12 000 текстов. Это позволяет дважды полностью дообучить модель на ноутбучной GPU и сохранить смысл сравнения. Test split не сокращался.

## 12. Как происходит обучение

Для каждого batch выполняются следующие шаги:

1. токены передаются в encoder;
2. применяется выбранный pooling;
3. классификатор вычисляет logits;
4. `CrossEntropyLoss` измеряет ошибку;
5. backpropagation вычисляет градиенты;
6. AdamW обновляет веса;
7. scheduler немного изменяет learning rate.

Использована mixed precision: часть операций выполняется в `float16`. На NVIDIA GPU это ускоряет обучение и уменьшает потребление видеопамяти. `GradScaler` предотвращает исчезновение слишком маленьких значений градиента при работе в `float16`.

## 13. Метрики

### 13.1. Precision

Precision отвечает на вопрос:

> Среди объектов, которые модель назвала этим классом, сколько действительно относятся к нему?

```text
Precision = TP / (TP + FP)
```

### 13.2. Recall

Recall отвечает на вопрос:

> Среди всех объектов данного класса сколько модель смогла найти?

```text
Recall = TP / (TP + FN)
```

### 13.3. F1-score

F1 объединяет Precision и Recall через гармоническое среднее:

```text
F1 = 2 × Precision × Recall / (Precision + Recall)
```

Если одна из двух метрик низкая, F1 также заметно снижается.

### 13.4. Почему используется macro averaging

Для каждого класса Precision, Recall и F1 считаются отдельно. Затем четыре значения усредняются с одинаковым весом:

```text
macro F1 = (F1_world + F1_sports + F1_business + F1_scitech) / 4
```

Macro averaging позволяет увидеть качество на каждом классе, не позволяя большому классу полностью определять итог. В данном датасете классы сбалансированы, поэтому macro F1 и accuracy близки.

## 14. Почему сравнение является корректным

В двух экспериментах одинаковы:

- модель `all-MiniLM-L6-v2`;
- train, validation и test;
- порядок и seed случайных операций;
- количество эпох;
- batch size;
- learning rate;
- optimizer и scheduler;
- максимальная длина текста;
- классификационный слой;
- способ выбора лучшего checkpoint.

Изменяется только pooling. Поэтому наблюдаемую разницу можно связать именно со способом построения вектора текста.

## 15. Выбор датасета

AG News выбран по следующим причинам:

- это открытый датасет на Hugging Face;
- задача является многоклассовой;
- классы понятны и сбалансированы;
- тексты достаточно короткие для обучения на ноутбучной GPU;
- полный test split содержит 7 600 примеров, поэтому метрики устойчивее, чем на маленьком учебном наборе.

## 16. Выбор модели

`sentence-transformers/all-MiniLM-L6-v2` — компактная BERT-подобная encoder-модель:

- 6 Transformer-слоёв;
- размерность скрытого вектора 384;
- поддерживается обычным `AutoModel` из Transformers;
- модель достаточно компактна для двух полных запусков на GPU с 8 ГБ памяти;
- она изначально предназначена для получения представлений предложений, что делает сравнение pooling содержательным.

В коде используется базовый Transformer encoder, а pooling реализован вручную. Готовый pooling из Sentence Transformers не используется, иначе нельзя было бы гарантировать одинаковое сравнение `mean` и `CLS`.

## 22. Анализ результата

`Mean pooling` оказался немного лучше на независимом test split. Возможное объяснение состоит в том, что усреднение напрямую использует контекстные представления всех токенов новости. Для тематической классификации полезные слова могут находиться в разных местах текста, поэтому их совместное усреднённое представление оказывается устойчивым.

`CLS pooling` также показал высокое качество. После fine-tuning токен `[CLS]` научился собирать информацию, достаточную для классификации. Разница менее одного процентного пункта, поэтому нельзя утверждать, что `CLS pooling` в целом является плохим подходом.

Результат относится к конкретному сочетанию:

- AG News;
- all-MiniLM-L6-v2;
- seed 42;
- выбранная подвыборка;
- два эпохи обучения;
- указанные гиперпараметры.

На другой модели или задаче победитель может измениться.

## 23. Ограничения эксперимента

1. Использована часть обучающего split, а не все 120 000 текстов.
2. Выполнен один запуск с одним seed. Для статистически более надёжного вывода нужны несколько запусков.
3. Проверялись только две стратегии pooling.
4. Максимальная длина ограничена 128 токенами, поэтому хвост длинной новости отбрасывается.
5. Датасет англоязычный, следовательно результат нельзя автоматически переносить на русский язык.

Эти ограничения не мешают выполнить цель лабораторной: обе стратегии реализованы в одинаковых условиях, метрики рассчитаны, а различия проанализированы.

## 24. Вывод

В работе была обучена encoder-модель для классификации новостей по четырём классам. Реализованы `mean pooling` и `CLS pooling`. Для обоих подходов использовались одинаковые данные, модель и настройки обучения.

На test split получены следующие значения macro F1:

- `mean pooling` — **0.9057**;
- `CLS pooling` — **0.9008**.

В данном эксперименте `mean pooling` показал лучший результат. Его преимущество составило около 0.49 процентного пункта по macro F1. Основное различие связано с более точным разделением классов `Business` и `Sci/Tech`.

Таким образом, стратегия pooling действительно влияет на итоговое качество, а её выбор следует проверять на конкретной задаче, а не делать только на основании общих предположений.
